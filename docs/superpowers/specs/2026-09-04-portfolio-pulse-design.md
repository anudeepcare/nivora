# NIVORA Portfolio Pulse — Design

## Goal
Make Portfolio the fastest place in NIVORA to understand whether the user's money is doing well, why, what risk is hidden, and what deserves action.

## Product hierarchy
Portfolio Pulse becomes the default top of the existing Portfolio page. The first mobile viewport answers: current value, portfolio health, immediate risk state, strongest driver/attention item, and one clear NIVORA summary. Existing holdings remain below Pulse.

## Time
Use 1D, 1W, 1M, 3M, 6M, YTD, 1Y, 2Y, 3Y, 4Y, ALL. Exact user portfolio performance starts when snapshots exist. Earlier periods may show current-holdings historical context only when data exists and must be labeled Current Holdings Backtest, never Actual Portfolio Performance.

## Benchmarks
Primary comparison is SPY and QQQ. Architecture also supports a NIVORA matched benchmark. Benchmark comparisons are secondary visual lines and can be toggled. No benchmark-relative claim is shown without sufficient history.

## Immediate intelligence
Day one uses current positions, cost basis, current prices, NIVORA thesis/opportunity/action evidence, allocation, concentration, cash/crypto exposure, and available risk overlay. It does not invent historical returns.

## Visual system
Mobile first. One hero, one performance visual, compact metric rail, return-driver visualization, concentration/risk visualization, then actionable decisions. Advanced details are click/expand. Avoid dashboard grids, excessive borders, gauges, and walls of metrics.

## Decision semantics
ADD means attractive individual evidence and acceptable portfolio sizing. HOLD means thesis intact. WATCH means evidence changed or needs confirmation. TRIM RISK is a portfolio-sizing conclusion and must not rewrite the individual stock thesis. AVOID/EXIT requires weak individual evidence. Portfolio risk changes sizing, not company truth.

## Safety and truthfulness
Never label cost-basis return as period performance. Never synthesize YTD/1Y user performance from today's holdings. Missing history is explicitly identified. Existing V65.10.1 company decisions and execution gates remain independent.
