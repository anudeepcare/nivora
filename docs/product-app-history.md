# Dated product app history

Official contract checked2026-11-18: https://sentisense.ai/docs/api/metrics/ and https://sentisense.ai/skill.md . Product lookup now offers an explicit Open app history action. One selected metric is loaded: app_review_count (integer new written reviews), app_rating (1–5 mean stars of those written reviews), app_all_ratings_count (new ratings including star-only, fractional allocated counts allowed), or app_all_ratings_avg (1–5 mean stars of those new ratings). All-rating store-total changes are spread evenly across days, so daily readings are not independent measurements. UI explicitly states this and does not derive adjacent-day trends, growth, adoption or consumer indexes.

30/90day rolling windows with real epoch-millisecond timestamps. Requests cap at100unmerged points, above the maximum daily buckets in those windows; projection bounds92points and rejects duplicate New York dates, nonascending/out-of-window timestamps, wrong enum, impossible stars and malformed numeric values. Missing values remain null. Dots use elapsed time and never connect missing periods; accessible table shows exact observations with NY date labels. No period averages are computed: valid star averages would require matching count weights, not a simple mean of daily averages. Empty200 means absent app coverage or no observations, never zero users/reviews.

Each request first verifies exact PRODUCT/publicSlug via existing entity detail, then one fixed /api/v2/metrics/entity/{publicSlug}/metric/{allowlistedMetric} call, both through sentisenseFetch shared account/credential guard. No internal KB IDs, ticker inference or consumer-index path. Metrics array has no mandatory identity echo, so identity is established by prior product response and fixed endpoint; optional mismatched echoes fail. No claim of atomic upstream identity across calls.
